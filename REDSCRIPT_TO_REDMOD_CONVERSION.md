# Converting Community Redscript to Cross-Platform REDmod Scripts

This guide lists the differences between **community redscript** (`.reds` files compiled by the
community redscript compiler) and the **REDmod script dialect** accepted by CDPR's official cross-platform REDmod
compiler (`.script` files, required for mods that run on console through mod.io). REDmod now accepts some of the community redscript syntax.

Unless stated otherwise, everything here was verified against the REDmod compiler and in game. The REDmod scripting guide is wrong in places;
where this guide disagrees with it, this guide reflects tested behaviour. Where something compiles but misbehaves at runtime, that is called out explicitly, because a
clean compile is **not** proof that converted code works.

## 1. Files and project layout

| Community | REDmod |
|---|---|
| `r6/scripts/<Mod>/*.reds` in the game folder | `<ModFolder>/r6/scripts/*.script` |
| Compiled automatically at game launch | Compiled ahead of time with `redMod.exe` (and again by mod.io cloud cooking on upload) |
| `.tweak` and `.yaml` TweakXL files | `<ModFolder>/r6/tweaks/*.yaml` only. `.tweak` files are **not** supported |
| `archive/pc/mod/*.archive` + `.xl` | Same location inside the mod folder: `<ModFolder>/archive/pc/mod/` |

A REDmod mod folder looks like this:

```
MyMod/
  about.json              <- generated by redMod.exe
  r6/
    scripts/*.script      <- you write these
    tweaks/*.yaml         <- you write these
    tweaks/*.json         <- generated from the .yaml
    cache/*.redscripts    <- generated compile output
  archive/pc/mod/         <- optional .archive, .archive.xl, .archive.json
```

Notes:

- **The mod folder name must not contain a period.** `MyMod_1.5x` silently fails to work;
  use `MyMod_1_5x`. Periods in file names are fine.
- `about.json`, the `.json` files next to tweak `.yaml` files, and everything under `r6/cache/`
  are produced by the compiler.
- The `.script` sources must still be present when you upload. mod.io recompiles them on its
  backend.
- If the mod registers ArchiveXL localization through an `.archive.xl` file, also ship an
  `.archive.json` file with the same content in JSON form.

## 2. Syntax differences

### Quick reference

| Feature | Community redscript | REDmod |
|---|---|---|
| Function keyword | `func` | `function`  |
| Event / callback handler | `cb func OnX(evt: ref<E>) -> Bool` | `event OnX(evt: E)` (no visibility, no return type) |
| Strong reference type | `ref<MyClass>` | `MyClass` (bare class name) |
| Weak / script refs | `wref<X>`, `script_ref<X>` | Unchanged |
| Dereferencing a `script_ref` | `Deref(x)` | Remove `Deref()` and use the value directly |
| Optional parameter | `opt x: Int32` | `optional x: Int32` |
| Null | `null` | `NULL` |
| TweakDBID literal | `t"Items.Foo"` | `T"Items.Foo"` |
| Resource path literal | `r"base\\..."` | `R"base\\..."` |
| CName literal | `n"Name"` | `n"Name"` or `'Name'` |
| Locals | `let x: Int32;` | `let x: Int32;` or `var x : Int32;` |
| Type inference | `let x = value;` | Often fails with `expecting ':'`. Give the type: `let x: T = value;` |
| Return type | `-> Bool` | `-> Bool` or `: Bool`. `-> Void` is allowed |
| Array type in return position | `-> [Int32]` | `-> array<Int32>` |
| Expression-bodied function | `func F() -> Bool = true` | `function F() -> Bool { return true; }` |
| `if` / `while` condition | `if cond {` | `if (cond) {` |
| For-in loop | `for x in arr { }` | Use an index with `while` or C-style `for` |
| C-style loop | Not available | `for (i = 0; i < n; i += 1) { }` |
| Object construction | `new MyClass()` | `new MyClass` (see [section 7](#7-stricter-checks-at-the-final-compile-stage)) |
| Casting | `x as Type` | `x as Type` or `((Type)(x))` |
| String interpolation | `s"Value: \(x)"` | Concatenate: `"Value: " + IntToString(x)` |
| Unsigned literal suffix | `1u` | `Cast<Uint32>(1)` |
| Empty array literal | `return [];` | `let empty: array<T>; return empty;` |

### Event handlers

```swift
// Community
protected cb func OnHoverOver(e: ref<inkPointerEvent>) -> Bool {
    this.SetHovered(true);
}

// REDmod
event OnHoverOver(e: inkPointerEvent) {
    this.SetHovered(true);
}
```

### Overriding a virtual method

Overriding a virtual method of a base class needs the `override` keyword:

```swift
private override function OnAttach() -> Void { ... }
```

### Reserved words

`name` is a type keyword and cannot be used as a parameter or variable name. Rename it
(`itemName`, `key`, and so on).

### Default array values

Array initializers work for locals, including fixed-size arrays:

```swift
var values : array<Int32> = [1, 2, 3];
var fixed  : Int32[3]     = [0, 1, 2];
```

A cast is **not** accepted inside an array literal. `[(Int32)MyEnum.A]` fails with
`unexpected TOKEN_SIMPLE_TYPE`. Build the array with `PushBack` instead, or use `as`.

## 3. Intrinsics and built-in functions

The REDmod compiler does not use the community intrinsic **function** forms. Use the operator or
method forms on the right.

| Community | REDmod |
|---|---|
| `Equals(a, b)` | `a == b` |
| `NotEquals(a, b)` | `a != b` |
| `IsDefined(obj)` (class instance, `wref`) | `if (obj)` |
| `IsDefined(entityId)` | `EntityID.IsDefined(entityId)` |
| `IsDefined(nodeRef)` | `GlobalNodeRef.IsDefined(nodeRef)` |
| `IsDefined(tweakDbId)` / `TDBID.IsValid` | `TDBID.IsValid(id)` |
| `ToString(x)` | `x.ToString()` where the type has it, otherwise `IntToString`, `FloatToString`, `BoolToString` |
| `EnumInt(e)` | `(Int32)e` or `e as Int32` |
| `IntEnum(i)` | `(MyEnum)i` or `i as MyEnum` |
| `ToVariant(x)` | `x as Variant` |
| `FromVariant(v)` | `v as Type` |
| `ArraySize(a)` | `a.Size()` |
| `ArrayPush(a, x)` | `a.PushBack(x)` |
| `ArrayPop(a)` | `a.PopBack()` |
| `ArrayClear(a)` | `a.Clear()` |
| `ArrayResize(a, n)` | `a.Resize(n)` |
| `ArrayContains(a, x)` | `a.Contains(x)` |
| `ArrayFindFirst(a, x)` / `ArrayFindLast(a, x)` | `a.FindFirst(x)` / `a.FindLast(x)` |
| `ArrayInsert(a, i, x)` | `a.Insert(i, x)` |
| `ArrayRemove(a, x)` | `a.Remove(x)` |
| `ArrayErase(a, i)` | `a.Erase(i)` |
| `ArrayLast(a)` | `a.Last()` |

An object also works as an operand of `&&`, `||` and `!` in a condition: `if (obj && obj.IsOn())`, `if (!obj)`.

### `Cast<T>`

- The generic argument is always required.
- Wrap anything with an operator in an extra pair of parentheses:

```swift
Cast<Int32>((a * b))   // compiles
Cast<Int32>(a * b)     // fails: unexpected '*', expecting TOKEN_CAST_AS
```

### Math

REDmod has a subset of the community math helpers.

- **Available:** `Min`, `Max`, `Abs`, `Clamp`, `SqrtF`, `PowF`, `LerpF`, `RandRange`,
  `RandRangeF`, `Deg2Rad`, `Rad2Deg`, the `Sin`/`Cos` family, `CeilF`, `FloorF`.
- **Not available:** `RoundF`, `AngleNormalize`, `AngleDistance`, `AngleApproach`,
  `LerpAngleF`.
### Game instance

`GetGameInstanceFromEngine()` returns the `GameInstance` from anywhere, including code with no player or context object to call `GetGame()` on.

## 4. Annotations and patching

### Wrapping: call the method by its own name

Community redscript calls the original through `wrappedMethod(...)`. REDmod does not recognize
`wrappedMethod`. Call the method **by its own name** instead:

```swift
// Community
@wrapMethod(CraftingSystem)
public func GetRecipesList() -> array<wref<RecipeData>> {
    let list = wrappedMethod();
    ...
}

// REDmod
@wrapMethod(CraftingSystem)
function GetRecipesList() -> array<wref<RecipeData>> {
    let list: array<wref<RecipeData>> = GetRecipesList();
    ...
}
```

### Visibility on annotated members

- On `@wrapMethod`, `@replaceMethod` and `@addMethod`, **omit** the visibility modifier
  (`public`, `private`, `protected`). Keep `final`, `static` and `const`.
- On `@addField`, write `let fieldName: Type;` with **no** visibility modifier.

### Available annotations

| Annotation | Notes |
|---|---|
| `@addField(Class)` | Adds a field. Works on any class except `importonly` ones (see below) |
| `@addMethod(Class)` | Adds a method. CDPR's reference says two installed mods adding the same method name to the same class make **all** script mods fail to load. In testing, two locally loaded mods that both added the same method to a vanilla class loaded fine, and other script mods kept working. Which version a call reaches was not tested, so still prefix added method names with your mod name |
| `@wrapMethod(Class)` | Wraps an existing method. Multiple wraps chain by load order |
| `@replaceMethod(Class)` | Replaces an existing method. Only the last-loaded replacement runs |
| `@prefix(Class)` | New in REDmod. Runs before the original; no need to call it. `this` works inside it. See the caution below |
| `@prefix("Class.Method")` | Prefix with a custom function name. Must return `Bool`. `true` lets everything run; `false` skips the original and any later prefixes, **and also skips the postfixes** (CDPR's reference says postfixes still run; they do not) |
| `@postfix(Class)` / `@postfix("Class.Method")` | New in REDmod. Runs after the original |

Execution order for a patched method: **wrap -> prefixes -> original (or replacement) ->
postfixes -> rest of the wrap**. The prefixes, original and postfixes all run inside the wrap's
call to the original.

**Caution with `@prefix(Class)` on methods that return a value.** In testing, a `@prefix(Class)`
on a vanilla method returning `Bool` ran, but the caller received `false` instead of the
original's `true`. Prefer `@wrapMethod` for any method whose return value matters.

**Patch only vanilla classes.** Any patch (`@wrapMethod`, `@prefix`, etc.) on a class declared by
your own mod compiles cleanly but **crashes the game at load**, logging
`patched Object " (null) " could not be resolved in base game or any module`. Change your own
classes directly instead.

**Wrapping global functions:** CDPR's reference writes this as `@wrapMethod()` with an empty
class argument, but that does not compile, and neither do `@wrapMethod`, `@wrapMethod("")` or
`@wrapMethod("FunctionName")` or `@wrapGlobal()`. No working syntax is known. Community redscript
has no global wrap either, so this is not a conversion problem. Its `@replaceGlobal()` (no
argument), which replaces a global function outright, does compile under REDmod; whether it takes
effect at runtime has not been tested.

### `importonly` classes cannot be extended

Check the class declaration in the game's script sources before patching an engine type:

```
importonly abstract class inkISystemRequestsHandler extends IScriptable   <- cannot take @addField
import class ModdingSystem extends IGameSystem                            <- fine
```

The REDmod compiler does **not** report an error for `@addField`/`@addMethod` on an
`importonly` class. It silently drops the member, and the only evidence is a
`'x' is not a member of ...` error at each place you use it (sometimes only visible in
`REDmodLog.txt`). Host the field on a different class.

### Modules

```swift
@module "MyMod.Runtime"     // at the top of the file, quoted string
@using "OtherMod.Utils"     // import another module
```

### Scriptable systems inside a module

In community redscript, a `ScriptableSystem` declared inside a module is looked up by its
module-qualified name. In REDmod, **always use the bare class name**, regardless of the
`@module` the class is declared in:

```swift
// Community
container.Get(n"MyMod.Runtime.MySystem") as MySystem

// REDmod
container.Get(n"MySystem") as MySystem
```

The wrong key returns `NULL` silently, and every later call on that `NULL` is also a silent
no-op.

### Conditional compilation

```swift
@if(ModuleExists("OtherMod.Runtime"))
@wrapMethod(SomeClass)
function SomeMethod() -> Void { ... }
```

Conditional functions, conditional `@addMethod` and conditional `@wrapMethod` all work: a version
loads only when its condition holds, and a conditional wrap with a false condition is simply not
applied. The limits are stricter than in community redscript. Every failure below aborts the
compile at the `final.redscripts` stage with **no error messages**:

- At most **two** versions of a conditional function may be declared.
- The two versions must not **both** use a positive `ModuleExists(...)`, even if they name
  different modules. Pair a positive condition with a negated one (`!ModuleExists(...)`), or use
  two negated conditions.
- A conditional `@addMethod` may have only **one** version.
- If both versions' conditions hold, the first declared one loads.
- If no version's condition holds, the function is not loaded, and any call to it fails the
  compile. Guard every caller with the same condition, or provide a version with the inverse
  condition.

## 5. Compiler limits with no community equivalent

### Locals are function-scoped and hoisted

Every `let`/`var` in a function is moved to the top of the function. This has two
consequences that community code does not expect:

1. **You cannot declare the same name twice in one function**, even in separate `if`/`while`
   blocks. The error is `Local variable 'x' is already defined`. Use distinct names.
2. **A local declared inside a loop body is one variable shared by every iteration.** It is
   not reset to empty or zero each pass. Declare it above the loop and reset it explicitly:

```swift
let found: array<ItemID>;
let i: Int32 = 0;
while (i < items.Size()) {
    found.Clear();               // required, or results accumulate across iterations
    this.CollectMatches(items[i], found);
    ...
    i += 1;
}
```

### Methods and fields on temporaries

Array methods can only be called on an array held in a variable:

```swift
sys.GetNames().Contains(x);        // fails: only arrays coming from variables call array functions
let names: array<CName> = sys.GetNames();
names.Contains(x);                 // ok
```

The same applies to struct fields:

```swift
widget.GetSize().Y;                // fails: Parent scope does not come from variable
let size: Vector2 = widget.GetSize();
size.Y;                            // ok
```

## 6. Strings and escapes

- **No string interpolation.** Concatenate with `+`.
- Supported escapes: `\n`, `\r`, `\t`, `\\`, and `\u{XX}` (a Unicode code point in hex inside
  braces, for example `\u{22}` for `"`).
- `\"` and `""` do **not** work (`Syntax error near: \"`), even though the community grammar
  allows `\"`.
- There is **no `\x` escape.** `\x22` compiles without error but produces literal garbage
  text instead of a quote. This is easy to miss: compiling cleanly does not prove an escape
  decodes correctly.

### Embedding double quotes (rich text markup, etc.)

The simplest approach, used by the vanilla game scripts themselves, is a CName literal. CName
literals use single quotes as delimiters, so they can contain `"` with no escaping:

```swift
let open: String = NameToString('<Rich color="') + color + NameToString('">');
label.SetText(open + text + "</>");
```

`\u{22}` also works:

```swift
"<Rich color=\u{22}" + color + "\u{22}>" + text + "</>"
```

## 7. Stricter checks at the final compile stage

`redMod.exe validate-mod-scripts -compile` runs in two stages:

1. **Validate** - checks your mod in isolation with a lenient front end.
2. **`final.redscripts`** - compiles your mod against the full game script base and writes `final.redscripts` and `final.redscripts.h64` to the mod's `r6/cache`.

A successful build prints one `Success` block and ends with
`Commandlet validate-mod-scripts has succeeded`. `Validate mod scripts success!` on its own does
**not** mean the mod compiles. These examples pass the first stage and fail at the
`final.redscripts` stage:

| Example | Error | Fix |
|---|---|---|
| `new MyClass()` | `unexpected '(', expecting ';'` | `new MyClass` |
| `return [];` | `unexpected ']'` | Return a typed empty local |
| Integer literals for `Float` parameters of game functions, e.g. `SetSize(445, 125)` | `Cannot match function to arguments` | `SetSize(445.0, 125.0)`. Give every literal a `.0`, even when none are mixed. (Integer literals passed to your own functions' `Float` parameters are accepted.) |
| `r"base\\..."` | `unexpected TOKEN_STRING` | `R"base\\..."` |
| Reading a `persistent` field of your own class from outside the class | `Cannot access protected property 'x'` (even if declared `public`) | Add accessor methods on the class |

### Failures with no error messages

If the `final.redscripts` stage hits enough errors, `redMod.exe` can abort before printing any
of them:

```
Validate mod scripts success!
Compiling final.redscripts
Compile mod scripts failed!
```

The compiler can also fail intermittently on certain unchanged sources. I (RMK) haven't figured out what causes that.

## 8. Known runtime bugs that affect converted code

These compile cleanly and fail only in game. Community redscript does not have them, so a mod
that worked before conversion can break in ways that look like a logic bug. I (RMK) have reported these to CDPR and they're aware of them.

### `@replaceMethod` is skipped by same-class callers (intermittent)

When a vanilla method calls another method of its own class, that call may not reach your
replacement. It returns the type's default value (`0`, `false`, empty) and runs **no** body at
all, neither yours nor the original. Writing `this.` or casting does not help. Calls from a
different class, including a subclass calling `super.X()`, reach the replacement normally.

Example: replacing `BaseScriptableAction.GetCost()` caused vanilla `PayCost()` (same class) to
read a cost of 0, making actions free with no error.

### A `@wrapMethod` body can run twice (intermittent)

For a single call, the wrapper may run twice, nested inside itself, while the original runs once.

I (RMK) had an instance of this which was fixed, but Deceptious still has this bug on one example.

### Repeated script calls reach a patch only once

When script code (your mod's or vanilla's) calls a wrapped or prefixed method several times, only
the **first** call goes through. Later calls skip the patch, and sometimes the original too, in
which case they return an empty default value. The calling function keeps running, so this can
look like the rest of it was skipped.

### Crash: discarding a directly returned, cast-produced enum

This crashes the game at runtime:

```swift
function InnerCast() -> EInputKey { let n: Uint64 = Cast<Uint64>(72); return (EInputKey)Cast<Int32>(n); }
function Outer() -> EInputKey { return InnerCast(); }

let k: EInputKey = Outer();   // fine
Outer();                      // CRASH: result discarded
```

It requires all three: an enum produced by a cast, a direct `return Call();`, and a caller that
discards the result. Either fix on its own prevents it.

**Fix at the source (CDPR's "safe cast"):** do each cast into its own local, then return the local.
With this `InnerCast`, the `Outer()` above can return directly and its caller can discard the
result without a crash.

```swift
function InnerCast() -> EInputKey {
    let stored: Uint64 = Cast<Uint64>(72);
    let numericValue: Int32 = Cast<Int32>(stored);
    let enumValue: EInputKey = (EInputKey)numericValue;
    return enumValue;
}
```

**Fix at the caller's side:** return through a local in the outer function.

```swift
function Outer() -> EInputKey { let result: EInputKey = InnerCast(); return result; }
```

As a general habit, cast into locals and return locals, rather than returning a cast or another
call's result directly.

## 9. Other features

### Persistent storage

REDmod provides **persistent storage** through `ModdingSystem`. Declare each value as an
`@addField` on `ModdingSystem`; the field name is the key.

```swift
@addField(ModdingSystem)
let myModVolume: Float;

let sys: ModdingSystem = GetGameInstanceFromEngine().GetModdingSystem();
sys.myModVolume = 0.8;                          // direct field access
sys.SetModsConfigValueByName(n"myModVolume", 0.8 as Variant);   // or by name
let v: Float = sys.GetModsConfigValueByName(n"myModVolume") as Float;
sys.SaveCurrentConfigsValue();                  // required to survive a game restart
```

Tested behaviour on PC:

- Only `Bool`, `Int32`, `Float`, `String` and `Uint64` survive a restart. `Int64`, `CName`,
  `Double`, `TweakDBID`, enums, and the small integer types (`Int8`, `Int16`, `Uint8`, `Uint16`,
  `Uint32`) work within a session but are lost on restart. CDPR's reference lists `Int64` as a
  supported type for keybinds, but `Int64` is actually saved as a boolean and lost; `Uint64` is
  the type that is stored as a keybind with its value intact.
- Values are **not** tied to a save file and persist across loading different saves.
- Values persist after the mod is uninstalled, so a reinstall does not start from defaults.
- Reading an unregistered name returns an empty `Variant` whose cast yields garbage (not `0`).
  Check `GetAllModsConfigsNames().Contains(name)` first (storing the array in a local).
- `GetAllModsConfigsTypes()` is **not** parallel to `GetAllModsConfigsNames()`. It lists every
  stored value, including entries left by uninstalled mods, grouped by type.
- On PC the values are written to
  `%USERPROFILE%\Saved Games\CD Projekt Red\Cyberpunk 2077\EnabledMods.json` under
  `mods_config`. Delete a mod's entries there (with the game closed) to reset it.

### Logging

```swift
import function ScriptLog(const text : ref<string>);

ScriptLog("value = " + IntToString(x));
```

Launch the game with `-logScripts` to capture the output.

- **Only one installed mod may declare this import.** If two loaded mods declare the same global
  `import`, the game logs `Scripts Mod loading Aborted Early due to conflict between mods` and
  loads no mods at all.
- Remove the import and all `ScriptLog` calls before releasing.

## 10. Compiling and testing

### Compile

`redMod.exe` ships with the game under `tools\redmod\bin`:

```powershell
cd "<game folder>\tools\redmod\bin"
.\redMod.exe validate-mod-scripts `
  -compile `
  -directory="<absolute path to your mod folder>"
```

### Test locally on PC

1. Compile as above.
2. Copy the **entire** mod folder (including `r6/scripts`) to `<game folder>\r6\c77\<ModFolder>`.
3. Launch `bin\x64\Cyberpunk2077.exe -LoadScriptMods -logScripts`.

## 11. Conversion checklist

Replacements:

- [ ] Rename `.reds` to `.script` and move to `<ModFolder>/r6/scripts/`
- [ ] Rewrite `.tweak` files as `r6/tweaks/*.yaml`
- [ ] `func` -> `function`
- [ ] `cb func OnX(...) -> Bool` -> `event OnX(...)`
- [ ] `ref<X>` -> `X` (keep `wref<X>` and `script_ref<X>`)
- [ ] Remove `Deref()`
- [ ] `opt` -> `optional`
- [ ] `null` -> `NULL`
- [ ] `t"..."` -> `T"..."`, `r"..."` -> `R"..."`
- [ ] `new X()` -> `new X`
- [ ] `wrappedMethod(...)` -> the method's own name
- [ ] Remove visibility modifiers on `@wrapMethod`, `@replaceMethod`, `@addMethod`, `@addField`
- [ ] Parenthesize every `if` and `while` condition
- [ ] Replace community intrinsics (`ArraySize`, `IsDefined`, `Equals`, `ToString`, ...)
- [ ] Replace `s"..."` interpolation with concatenation
- [ ] Replace `for x in arr` with an index loop
- [ ] Replace `= expr` function bodies with `{ return expr; }`
- [ ] Replace `[T]` array types with `array<T>`
- [ ] Replace `return [];` with a typed empty local
- [ ] Add `.0` to integer literals passed to game functions' `Float` parameters
- [ ] Replace `1u`-style suffixes with `Cast<Uint32>(...)`
- [ ] Add explicit types to `let x = ...;` where inference fails
- [ ] Add `override` to methods that override a virtual method
- [ ] Rename parameters and locals called `name`
- [ ] Give every `Cast` its generic, and parenthesize arguments with operators: `Cast<Int32>((a * b))`
- [ ] Use the bare class name in `GetScriptableSystemsContainer(...).Get(n"...")`

Other things to review:

- [ ] Duplicate local names within one function, and locals declared inside loops
- [ ] Array methods or struct fields accessed on a call result
- [ ] Casts inside array literals
- [ ] `persistent` fields read from outside their class (add accessor methods)
- [ ] `@addField`/`@addMethod` targets that are `importonly`
- [ ] Unsupported math helpers (`RoundF`, angle helpers)
- [ ] String escapes (`\"`, `\x..`)
- [ ] `.archive.json` next to every `.archive.xl` that registers localization
- [ ] Full compile reaches `Commandlet validate-mod-scripts has succeeded`
