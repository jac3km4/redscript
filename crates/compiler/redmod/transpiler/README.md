# redscript-redmod-transpiler

Strict community REDscript → REDmod source transpilation. Bodies come from shared typed
IR; retained source supplies declaration order, imports, docs and annotations.
Unsupported input returns diagnostics, never partial output. The
[language guide](../../../../docs/README.md) explains both dialects; shared
[future work](../../../../docs/language-future-work.md) tracks unresolved behavior.

## API conventions

- Use `analyze_sources`, then `transpile_selected`, or the combined `transpile_sources`.
  All input files are analyzed as community sources; only selected `FileId`s are
  emitted. Library callers must supply boot/engine dependencies explicitly and
  leave them unselected; the library does not implicitly load them. The
  `transpile-redmod` CLI always loads boot as an implicit, unselected dependency,
  even with `--bundle`. A bundle supplies baseline engine symbols, not a replacement
  for boot intrinsics. CLI `--dependency` inputs are analyzed but not emitted.
- Low-level `transpile` accepts `TranspileModule` bindings from structural
  `DeclarationPath`s to `ResolvedDeclaration`s. Retained AST, bindings, IR and
  symbols must come from the same successful compilation.
- Never associate bodies by spans, pointer identity or overload position.
  Automatic association uses resolved names/types/signatures and rejects inferred
  signatures, conditional declarations and multiple wrappers when ownership is
  unprovable. Explicit bindings are a caller contract, not proof that an unrelated
  same-name body belongs to a declaration.
- Inactive variants need separate analysis and actual bodies; the single-unit API
  does not synthesize them. Duplicate identities and competing replacements fail,
  including replacements in unselected dependencies.
- Diagnostics retain declaration paths and source spans; `display(&sources)`
  renders `REDMOD_TRANSPILE` excerpts. Generated byte mappings can overlap for nested
  statements. The core transpilation API performs no filesystem operations.

## Supported subset

The transpiler handles explicit typed signatures/locals, ordinary calls/operators/casts,
structured IR control flow, lowered for-in/interpolation, selected dynamic-array
intrinsics, verified primitive/reference and struct defaults, overrides, and uniquely
associated patches.

### Declarations, naming and formatting

- **Naming hygiene:** Local names prefer authored spellings with deterministic disambiguation
  by IR identity. Compiler temporaries receive purpose-based names (`arrayLiteral`, `index`,
  `iterable`) or contextual names (`valuesLiteral`, `itemIndex`) when associated with an
  authored binding. Authored names are allocated first and protected from collisions.
- **Layout and style:** Class members are indented, major declarations are separated by blank
  lines, and expression emission uses target precedence/associativity to eliminate redundant
  parentheses.
- **Control-flow simplification:** Final single-branch checks with `else { break; }` directly
  inside `while (true)` become early-exit guards without moving condition prefixes or changing
  break/continue targets. Generated guards simplify Boolean negation and equality checks while
  preserving native operator selection without inverting ordered comparisons.
- **Numeric formatting:** Emits plain `0` for Int32 defaults and avoids redundant cast
  parentheses; other numeric widths retain explicit casts.

### Intrinsics, types and coercions

- **`ToString`:** Emits without an operand allowlist. Native primitive mappings and string
  identity are preserved; other operands use REDmod's `value as String` conversion. Weak
  operands retain their explicit strong-reference conversion before string conversion.
- **`NameOf`:** `NameOf<T>()` (and legacy `NameOf(T)`) emits a `CName` literal using the
  community backend's compact resolved type name rather than REDmod's type spelling.
- **Intrinsic classification:** Every intrinsic is classified explicitly rather than emitted
  as an ordinary call.
- **`IsDefined`:** Reference `IsDefined` tests accept an immediate weak-to-strong promotion
  without emitting a strong temporary: the weak handle is compared directly with `NULL`.
- **Target coercions:** Immediate typed initializers, assignments, returns and unambiguous
  arguments can combine strong/weak conversion with a class upcast. The destination must
  retain the conversion's reference kind; downcasts, competing overloads and nested
  conversion chains remain rejected.

### Initializers and in-place construction

- **Declaration fusion:** Unconditional first assignments and non-array defaults merge with
  their local declarations at the existing execution site when no earlier or self-reference
  exists. Other declarations remain hoisted: branch/loop initialization, array resize/clear
  operations and repeated default resets are never moved or dropped.
- **Array construction:** Shared lowering constructs direct array literals in eligible fresh
  lexical locals, avoiding an intermediate array and copy. Existing assignments, repeated
  loop-body declarations, hoisted/native-policy bindings and non-array coercions retain
  temporaries. Empty literal temporaries are cleared on every execution in emitted source.
- **Provenance tracking:** Shared IR retains declaration provenance (lexical scope identity,
  full source span, initialization kind/site, and lexical vs. hoisted storage). This
  metadata does not widen declaration fusion into branches or loops.

### Callbacks and references

- **Callbacks:** Callbacks require a non-const Bool return contract, matching REDmod's
  implicit Bool events. Their return expressions are preserved, not evaluated into discard
  locals followed by invalid bare returns. Void and other community callback result contracts
  fail with a source diagnostic rather than silently changing ABI. Calls relying on callback
  results remain rejected.
- **Script references:** Assignments to `script_ref` destinations are emitted unchanged.
  In REDmod they write through the reference rather than rebinding it as community source
  does; this semantic difference is not diagnosed. Preserving community rebinding is
  [future work](../../../../docs/language-future-work.md).

### Compound method receivers

Strong and weak class-reference call chains, existing local-rooted fields and
conditional receivers stay inline, preserving Context/argument and lazy execution
boundaries. REDmod supplies implicit weak-to-strong receiver promotions.
Field assignments through local strong or weak class handles also stay inline.
Struct write-back, array places and compound script-reference receivers remain gated. See the
[receiver contract and bytecode evidence](../../../../docs/redmod-language.md#bounded-compound-method-receivers).

### Compound field reads

Bounded field reads stay inline: class call/conditional chains, nested local-rooted
class/struct fields, and `Deref(localScriptRef).visualStateData.m_isIconic`.
Struct member reads require a variable-rooted parent scope in official v1.2.2;
call/conditional-rooted struct paths remain rejected. Writable places, `out`,
mutable struct receivers and array gates are unchanged. See the
[field-read contract and official evidence](../../../../docs/redmod-language.md#bounded-compound-field-reads).

### Native script-reference borrows

Immediate exact non-out native `script_ref<T>` parameters support nonlocal
`AsRef` operands without moving evaluation or materializing hoisted copies.
Ordinary native calls and operators share per-parameter conversion handling and
overload checks, including mixed string concatenation. There is no operator-name
or pointee-type allowlist; escaping and context-free borrows remain rejected.
See [bounded borrows and lifetime evidence](../../../../docs/redmod-language.md#bounded-native-and-scripted-script-reference-borrows).

### Struct defaults and resets

All struct defaults uniformly emit `Type()`, delegating construction to the engine
rather than enumerating individual fields or inferring layouts from imported fields.
Explicit positional constructor expressions retain their authored field arguments.

The transpiler can omit a local's first, unconditional default initialization when
backward liveness proves no read occurs before a whole-local overwrite. Branches and
loop back edges participate in that proof; reads, borrows, `out` arguments, and partial
field writes keep the default. Repeated or conditional declarations retain explicit
resets at their execution sites, and switch occurrences are conservatively treated
as reads. This does not infer native layouts or change Variant reset behavior.

### Literal conventions

Emit decoded values, not community escape spellings. Official String/CName
backslashes are raw: `\u{22}` is text, not an escaped quote. Strings use double
quotes; CNames use the verified single-quote form. LF multiline values are supported;
embedded delimiters, NUL and unverified controls fail with typed `LiteralError`s.
Resource/Tweak literals reject unverified backslash/multiline forms.

Finite Float values use round-tripping plain decimal spelling with a decimal
point and signed zero. Unsupported integer ranges, nonfinite values and Doubles
not exactly representable by the supported Float-cast path fail rather than narrow.
Native parser acceptance alone does not establish transpiler numeric support.
All Uint32 values are supported without widening to Int64: expressions emit
`Cast<Uint32>` from the signed 32-bit bit pattern, while field defaults use
unsigned decimal literals because the native field-default grammar rejects casts.
Explicit enum storage and its representable signed/unsigned values are preserved;
wide enum initializers use unsuffixed native literals. See
[enum storage](../../../../docs/community-language.md#explicit-enum-storage) for the Int64 minimum restriction
and bundle signedness limitations.

## Remaining work

| Gap | Approach |
| --- | --- |
| Inferred signatures, conditions, multiple wrappers and cross-module patches | Add finalized source identity facts and a variant-aware transpilation plan |
| Array prefixes crossing lazy branches, switch matchers or prior operands | Preserve execution-site prerequisites in shared lowering before relaxing source guards |
| Unsafe receivers, temporary/nonlocal places, and context-free strong/weak coercions | Add context-aware place/reference lowering; never mutate a copy as a substitute |
| Zero-member-less enum, Variant and fixed-array default resets | Verify target initialization/reset behavior |
| Const locals | Preserve verified initialization and mutation semantics; currently rejected rather than emitted as mutable |
| Array sort/custom operations, `LongIntEnum`, variant inspection, more `IsDefined` types | Add resolved typed mappings and official fixtures per operation |
| `editable`, `instanceeditable`, `inlined`, `replicated`, `testonly` transpilation | Preserve verified declaration semantics rather than dropping flags |
| Import-aware target names, unknown metadata, global replacements and broader conditions | Extend declaration/target planning without emitting rejected qualified calls or guessing ownership |
| Wider integer/Double ranges and literal controls | Establish exact official constant-pool values before accepting new spellings |

Const locals return a source diagnostic: native scalar const initialization does
not share the community contract, so simply emitting `const` is not a safe fix.
See [const semantics](../../../../docs/community-language.md#const-parameters-and-locals). Custom generics,
lambdas/captures/function values, `mixedRef` and `neverRef` class-value emulation
have no fallback. Assets/tweaks conversion, system-lookup
rewriting and runtime patch workarounds are outside the current transpiler.

## Packaging and official validation

`package::publish_mod` stages authored scripts, optionally validates them, then
renames the inner mod into place. It rejects unsafe/colliding paths and existing
destinations; failure removes staging. Publication is atomic for visibility, not
crash durability. A cooperating-publisher lock does not protect against unrelated
processes creating the destination. `package::source_at` resolves generated byte
offsets to retained source mappings.

`validate::OfficialValidator { executable, timeout }` runs an explicitly trusted
absolute executable with bounded execution and file-backed logs. Success requires
exit success, the final commandlet success marker and fresh nonempty compiled/hash
artifacts; old caches are not reused. The tool has normal local access and may
write logs beside its executable. Use `validate_with_root` or
`publish_mod_with_root` when base-game blobs require an explicit absolute root.
The CLI exposes this through `transpile-redmod`, `--redmod` and `--game-root`.
Transpilation remains strict; `compile`/`lint --runtime-compatible` does not relax
its unsafe-prefix or const-local restrictions.

## Tests

```sh
cargo test -p redscript-redmod-transpiler --locked
cargo test -p redscript-redmod-transpiler --all-features --locked
cargo clippy -p redscript-redmod-transpiler --all-targets --locked -- -D warnings
```

Use authored emitted-source/diagnostic snapshots; direct assertions cover values,
identity and provenance. Default tests require no installation. Opt-in probes
against a trusted local official compiler are described below.

### Official evidence

Opt-in integration tests run against a trusted local official compiler (set
`REDMOD_EXE` and `REDMOD_GAME_ROOT`). They use a 60-second bound per invocation
and retain artifacts under `target/redmod-official/`; they establish compilation,
typing, and code-generation behavior, not runtime behavior:

- `official` — mod identity, fresh compilation, cache-reuse rejection, decoded
  String/CName pools, semicolon-event contracts, enum-storage bounds, inline
  initializer acceptance, and zero-argument struct construction.
- `struct_defaults` — generated positional defaults for nested structs, and
  repeated zero-argument resets for `Vector2`, `ResRef`, `ItemID`, `inkAnimOptions`
  and `stimInvestigateData` at entry and on the loop back edge.
- `suite` (`uint32_literals`) — exact Uint32 constants and field defaults.

Reproduce individual probes with `--ignored --nocapture`:

```sh
cargo test -p redscript-redmod-transpiler --locked --test official -- --ignored --nocapture
cargo test -p redscript-redmod-transpiler --locked --test struct_defaults -- --ignored --nocapture
cargo test -p redscript-redmod-transpiler --locked --test suite uint32_literals -- --ignored --nocapture
```

See [future work](../../../../docs/language-future-work.md) for remaining capabilities
and the [investigation archive](../../../../docs/language-investigations.md) for
historical official observations, which are not a certification of current HEAD
or game behavior.
